# Presentation Projection Contract

Presentation projection is an **explicit opt-in derived sibling**. It places a verified canonical PNG on a
registered raster surface without changing the source SVG or canonical PNG.

## Authority And Default

- The default handoff stays editable SVG + the exact 2× PNG produced by `scripts/render.mjs`.
- Ordinary authoring and render requests do not invoke, recommend, or fall back to projection.
- Once projection is explicitly requested, omitting `--surface` selects bundled `paper-notebook`. This is command
  routing inside the opt-in sibling, not a fallback from canonical rendering. An explicit manifest always wins.
- A projection PNG is additional output. It is never named or described as the canonical PNG.
- Projection failure has its own classification and cannot invalidate an already accepted canonical artifact.
- Projection reads the source SVG and canonical PNG; it never rewrites either file.

## V1 Command Boundary

```text
node scripts/projection.mjs build --svg diagram.svg --canonical-png diagram.png \
  --out diagram.paper.png \
  --signature kyungseo.github.io

node scripts/projection.mjs verify --receipt diagram.paper.receipt.json --out diagram.paper.png
```

`build` must invoke the full `render.mjs` CLI entrypoint into temporary storage. Raw Chromium calls and imported
render helpers are not equivalent: the entrypoint owns source lint, conditional typography/layout gates, browser
identity, exact dimensions, and complete-PNG verification.

## Canonical Verification Classifications

| Classification | Meaning | User action |
| --- | --- | --- | --- |
| `pass` | Full render gate passed and regenerated bytes equal the supplied PNG | Continue |
| `canonical-pair-invalid` | Supplied PNG is malformed or not the SVG's exact 2× dimensions | Recreate the canonical PNG |
| `canonical-validation-failed` | Full `render.mjs` entrypoint returned non-zero | Fix the reported canonical gate failure |
| `canonical-bytes-mismatch` | Regeneration passed and dimensions match, but bytes differ | Rerender in the current environment/session and retry |

`canonical-bytes-mismatch` records `cause: unavailable`. Equal dimensions and unequal bytes do not prove whether
the cause was a browser/font environment change or mutation of the supplied PNG.

The projection receipt contains a `canonical_verification` subrecord with the render exit, disclosed renderer
tuple, regenerated digest, supplied digest, and classification. An external canonical receipt may be linked by
hash when available but is not invented when the canonical workflow did not create one.

## Surface Manifest V1

The manifest is strict JSON. Unknown fields fail closed.

- `schema_version`: exactly `1`.
- `id`: stable lowercase hyphenated identifier.
- `asset`: safe package-relative or manifest-relative PNG path, exact SHA-256/dimensions, `srgb`, license,
  redistribution state, and provenance.
- `content_plane`: integer-pixel `rect`, or ordered `quad` points (`tl,tr,br,bl`).
- `safe_area`: rectangle containing every content-plane corner.
- `minimum_projected_scale`: at least the global `0.5` floor. A template may tighten, never relax, the floor.
- `canvas_adaptation`: optional four-connected outer-canvas mask. Bundled surfaces use
  `boundary-connected-dominant-border-exact-rgba`: the most frequent exact RGBA value on the canonical border
  must meet a declared share floor (`0.5` in the starter set), and only matching pixels connected to that border
  are removed. The fixed-color exact mode remains available; equal-colored interior cards stay in both modes.
- `blend_profile`: one registered fixed profile: `source-over-v1`, `ink-on-surface-v1`, or `matte-display-v1`.
- `layers`: only plane-behind/outside `shadow` and background-only seeded `grain`/`ambient_gradient`.
- `signature_slot`: bounded slot with `default: null` and a fixed color; signature is user-provided only.
- `required_attribution`: license-owned text or `null`; a user signature cannot replace it.

Paths that are absolute, use `..`, contain backslashes, or have URL schemes are invalid. V1 user surfaces are
raster-only. Arbitrary SVG/HTML, remote resources, active content, and silent image conversion are unsupported.

Generated assets additionally require the generation tool/identifier, date, terms basis, human disposition,
source SHA-256, any strict normalization record, and an explicit review that no identifiable existing artwork,
trademark, or character appears. Public redistribution fails closed when rights evidence is missing. A normalized
asset never erases its generation-source lineage.

## Bundled Surface Set

The v1 starter package includes three 4:5-oriented surfaces selected by Owner audition:

| Surface | Character | Geometry | Registered blend |
| --- | --- | --- |
| `paper-notebook` | warm, familiar, lightly tilted paper | quad | `ink-on-surface-v1` |
| `gallery-wall` | neutral architectural frame | rect | `ink-on-surface-v1` |
| `portrait-monitor` | product/context framing without a branded device | quad | `matte-display-v1` |

Each manifest lives under `references/presentation/surfaces/`; users may replace it with their own local strict
manifest and raster. `paper-notebook` is the default only after projection itself is requested. The bundled set is
intentionally restrained: repeated-use identity comes from material, negative space, and bounded perspective,
not props or trend motifs.

## User Signature

`--signature` is optional and supports 1–64 characters from the deterministic v1 ASCII set
(`A-Z a-z 0-9 space . / : @ _ -`). It uses a bundled 3×5 bitmap glyph table, right-aligns inside the registered
slot, never touches the content plane, and records the exact value plus its SHA-256 in the receipt. Omitting the
flag writes no signature. Required asset attribution remains a separate non-substitutable field.

## Content Protection And Layers

The machine-protected authority in v1 is the **whole content plane**, not guessed semantic regions.

- Any opaque foreground/decor intersection with the content plane fails.
- V1 also rejects translucent grain, light, highlight, or reflection over the content plane.
- Shadow is behind the projected PNG; grain and ambient gradient are applied to the background before projection.
- The optional boundary-connected exact canvas mask removes only a registered exact outer-canvas component from
  the derived source buffer. The dominant-border mode resolves one exact RGBA value deterministically, rejects a
  border without the declared majority, and records the resolved value, border share, and masked-pixel count in
  the receipt. It does not mutate the canonical PNG or infer semantic regions.
- `ink-on-surface-v1` uses fixed 224/256 chroma reduction followed by per-channel multiply, so canonical white
  admits the registered material and vivid colors behave like restrained print. `matte-display-v1` uses the same
  fixed chroma reduction with source-over to preserve a luminous screen. `source-over-v1` preserves source color.
- Profiles are manifest-selected and receipt-bound. Arbitrary opacity, filter expressions, color matrices, or
  per-run tuning are not accepted in v1.
- Highlight/reflection and semantic-region occlusion are deferred until a later contract can measure them.
- Minimum projected scale is a geometry floor, not machine certification of legibility. Target-size readability
  stays part of visual QA and Owner audition.
- Canvas adaptation removes the canonical canvas from the derived source buffer, so the canonical canvas/ink
  contrast result does not transfer automatically to the registered surface. V1 assigns that derived contrast
  judgment to target-size surface audition; dark or custom surfaces need a separate contrast-floor contract before
  they can claim machine-checked readability.

Surface choice remains a human presentation decision, not automatic routing: dense hairline or multi-band layouts
usually retain stronger visual grouping on rect or low-tilt surfaces, while stronger quad perspective is better
suited to centrally grouped diagrams. This is usage guidance, not a geometry acceptance rule.

This strict boundary leaves room for a later translucent integration class without misrepresenting today's
machine evidence.

## Deterministic Compositor

The compositor uses Node standard library only:

- PNG: non-interlaced 8-bit RGB/RGBA, sRGB/no-ICC subset.
- Decoder: explicit PNG unfiltering; unsupported critical/ancillary color-profile forms fail closed.
- Mapping: pure-JS inverse rect/quad transform.
- Resampling: `bilinear-rgba8-v1`.
- Material integration: registered integer `source-over-v1`, `ink-on-surface-v1`, or `matte-display-v1` only.
- Encoder: RGBA8, Paeth scanline filter `4`, zlib level `9`, strategy `Z_FIXED`.
- Receipt: codec/kernel IDs, Node/zlib tuple, geometry, all input digests, and output digest.

Chromium canvas, CSS perspective, external image libraries, and implicit encoder defaults do not participate in
composition. Same-environment byte regeneration is the output oracle; cross-environment claims stop at receipt and
invariant parity.

## Failure Atomicity

All validation occurs before final output writes. The output is written to a sibling temporary file, synced, and
atomically renamed. Its digest is then bound into a receipt that is also temp-written, synced, and atomically
renamed last. A final output without a valid matching receipt is incomplete and `verify` returns red. Retry must be
deterministic and may replace only the requested derived output/receipt, never canonical inputs.

## Asset And Audition Budget

- Selected presentation raster assets: at most `10 MiB` total and `3 MiB` each, measured as the sum of exact PNG
  file bytes (not filesystem allocation). Manifests count separately as part of the final package-tree budget.
- Final `skills/svg-infographic` package tree: at most `30 MiB`.
- Candidate scratch assets do not enter the package.
- Same-input comparison is followed by a three-input repeat-use audition for finalists. Prefer restrained
  material, negative space, and quiet framing over novelty props, trend stickers, or scene gimmicks that become
  stale after a few uses.
