# 버전 관리

*[English (canonical)](./VERSIONING.md) · 한국어*

이 카탈로그의 각 스킬은 자기 버전을 갖습니다. 카탈로그 자체에는 버전이 없습니다.

스킬을 설치했다면 확인해야 할 버전은 그 스킬의 `SKILL.md`에 선언된 값이고, 확인해야 할 이력은 그 스킬의
`CHANGELOG.md`입니다. 스킬 하나를 릴리스해도 다른 스킬의 번호는 바뀌지 않습니다 — 릴리스가 건드리는
유일한 공유 표면은 루트 README 카탈로그 표에서 그 스킬이 차지하는 행 하나입니다.

## 전환 상태

**이 저장소는 스킬별 버전 관리로 옮겨가는 준비 단계이며, 아직 그 방식으로 운영하고 있지는 않습니다.**

| | 상태 |
| --- | --- |
| 각 `SKILL.md`의 `metadata.version`, 스킬별 `CHANGELOG.md`, README `버전` 열 | **준비됨.** 아래에서 설명하는 baseline 산출물이 이미 존재합니다 |
| 설치 시 고정할 버전 | **카탈로그 태그 `v0.8.0`이 여전히 유효한 pin입니다.** 그대로 사용하세요 |
| `<name>/vX.Y.Z` 태그와 스킬별 릴리스 | **아직 운영하지 않습니다.** 발행된 것이 없습니다 |
| 버전 증가 규칙 | **아직 발효되지 않았습니다.** [버전이 올라간다는 것의 의미](#버전이-올라간다는-것의-의미) 참조 |

전환은 cutover commit 하나에서 일어나며, 그 시점에 namespaced 태그가 만들어지고 아래 규칙이 적용되기
시작합니다. 그전까지 이 문서는 목표 상태와 그것을 위해 미리 준비해 둔 산출물을 설명합니다. cutover
이후에만 효력이 생기는 항목은 그렇다고 따로 표시했습니다.

## 버전이 기록되는 곳

| 표면 | 역할 |
| --- | --- |
| `skills/<name>/SKILL.md` → `metadata.version` | 설치된 패키지가 선언하는 버전 |
| `skills/<name>/CHANGELOG.md` | 그 스킬만의 이력 |
| 루트 `README.md` / `README.ko.md` 카탈로그 표의 `버전` 열 | 각 스킬의 공개된 현재 버전 |
| Git 태그 `<name>/vX.Y.Z` | *(cutover 이후)* 어느 commit에서 릴리스했는지 |

"이 스킬의 현재 버전이 무엇인가"에 대한 기준은 카탈로그 표입니다. 릴리스는 패키지와 그 표를 함께
갱신하므로 둘이 어긋나지 않습니다.

## CHANGELOG heading 문법

이 절은 **parser contract**입니다. 자동 검사가 이 heading을 읽으므로 가독성 문제를 넘어 형식 자체가
계약입니다.

### 릴리스된 항목

```
## [X.Y.Z] — YYYY-MM-DD
```

- heading 수준은 정확히 `##`입니다.
- 버전은 대괄호 안에 두고 숫자 세 자리를 정확히 씁니다. build metadata와 pre-release suffix는 쓰지
  않습니다 — 릴리스 태그에 걸린 제약과 같습니다.
- 구분자는 em dash(`—`, U+2014)이고 양옆에 공백 한 칸씩 둡니다.
- 날짜는 ISO-8601(`YYYY-MM-DD`) 형식이며 릴리스 날짜입니다.
- 항목은 최신순으로 정렬합니다.

**예외가 하나 있습니다.** 각 스킬의 `0.8.0` baseline 항목은 스킬별 릴리스가 아직 없었기 때문에, 번호를
이어받은 카탈로그 `v0.8.0`의 릴리스 날짜를 그대로 씁니다. 그 뒤의 항목은 모두 실제 스킬별 릴리스이고
자기 날짜를 갖습니다. 검사는 날짜가 아니라 버전을 읽으므로 이 예외가 검사에 영향을 주지는 않습니다.

### 아직 릴리스하지 않은 작업

`## [Unreleased]` 절은 선택 사항이고, 둘 경우 릴리스된 모든 항목 위에 옵니다. 날짜는 붙이지 않습니다.
버전은 작업 중이 아니라 release gate에서 확정하므로, 그전까지의 메모를 `[Unreleased]` 아래에 모아 두는
것이 의도된 방식입니다.

### 검사가 파일을 읽는 방식

**최상단 릴리스 항목**은 위에서부터 읽어 내려갈 때 대괄호 안이 `X.Y.Z` 형식과 일치하는 첫 `##`
heading입니다. `[Unreleased]` heading은 버전으로 보지 않고 건너뜁니다.

그 항목의 버전은 같은 패키지 `SKILL.md`의 `metadata.version`과 같아야 합니다. 값이 다르면 릴리스가 둘 중
하나를 갱신하지 않았거나, 누군가 한쪽을 직접 편집했다는 뜻입니다.

## 버전이 올라간다는 것의 의미

**아래 규칙은 cutover 이후의 변경에 적용됩니다.** [전환 상태](#전환-상태)에서 설명한 baseline 준비 작업
자체는 버전 증가가 아닙니다 — 시작점을 만드는 행위이기 때문입니다. baseline을 완료한 시점부터 cutover
commit까지는 `skills/**`가 동결되므로, 그 구간에서도 버전 증가가 발생할 수 없습니다.

릴리스의 근거는 패키지 **payload**의 변경입니다. payload는 `skills/<name>/` 아래 전부에서
`metadata.version` 값과 이 CHANGELOG를 뺀 나머지입니다. 그 둘은 릴리스가 만들어 내는 기록이지 릴리스의
이유가 아니므로, 둘만 바꾼 것은 릴리스가 되지 않습니다.

| 변경 | 단계 |
| --- | --- |
| 사용자가 관찰할 수 있는 동작·계약·출력이 바뀜 | minor |
| 그 밖의 변경 | patch |
| `1.0.0` 이상으로의 승격 | major — owner의 명시적 승인이 필요합니다 |

변경의 성격이 모호하면 파일 위치로 판단합니다. `SKILL.md` 본문, `references/`, `scripts/`(fixture 제외),
`agents/`는 기본이 minor이고, `README*.md`, `LICENSE*`, `assets/`, fixture는 기본이 patch입니다. 릴리스에서
기본값을 어느 방향으로든 조정할 수 있지만, 그 사유를 CHANGELOG 항목에 적어야 합니다.

`skills/<name>/` 바깥의 변경 — 루트 README, `docs/`, `examples/` — 은 어떤 스킬의 버전도 올리지 않습니다.

## Baseline

네 스킬 모두 `0.8.0`에서 시작합니다. 이 숫자는 각 스킬이 그만큼 바뀌었다는 뜻이 아니라 전환 지점을
가리킵니다. 그전까지는 카탈로그 버전 하나가 모든 스킬을 한꺼번에 덮었고, 두 이력이 이어지도록 그 번호를
그대로 가져왔습니다. 0부터 다시 시작하지 않은 이유가 여기 있습니다.

*(cutover 이후)* 나중에 추가되는 스킬은 `0.1.0`에서 시작합니다. 그쪽은 실제 첫 릴리스이기 때문입니다.

카탈로그 태그 `v0.1.0`부터 `v0.8.0`까지와 그 릴리스는 계속 공개돼 있고 설치할 수 있습니다. 이동하거나
삭제하거나 재사용하지 않습니다.
