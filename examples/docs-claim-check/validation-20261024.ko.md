## 최초 설정 실패와 수정

첫 Opus S1은 custom skill이 등록되지 않는 제한 프리셋으로 실행했습니다. Skill 호출이 실패한 뒤 모델이
디렉터리 목록 명령을 시도했고 guard가 거부했습니다. 이후 계약 파일을 직접 읽었습니다. 결과에 시도 사실은
밝혔지만 검토가 무효라고 명시하지 않았습니다. 설치본 호출 통과나 행동 계약 준수로 집계하지 않습니다.

모델 요청 없는 초기화 비교에서 동일한 실제 package와 나머지 옵션을 유지한 채 `--restricted`만 제거하면
스킬이 등록되는 차이를 확인했습니다. 이 비교가 분리한 것은 초기화 시 preset 차이이며, 모델 실행 간
모든 조건이 같았다는 뜻은 아닙니다. 최초 실행은 공용 project package를 사용했고 재확인·이후 실행은
사례별 실제 package를 사용했습니다. byte-identical인 사용자 수준 사본도 존재했지만, 성공한 Skill 결과의
base directory는 공용·사용자 사본이 아닌 사례별 경로였습니다. 정확한 경로 읽기 guard, 명령 거부, 도구 목록, 권한 모드와 빈 MCP 설정은
유지했습니다. 이후 모든 실행은 prompt를 보내기 전에 등록을 확인했습니다. Opus S1 재확인 1회에서는 설치본이
로드됐고 핵심 판정을 통과했습니다. 최초 실패는 기록에서 제외하지 않습니다.

## 연관 스킬에 미치는 영향

출력 section, 판정 상태, 근거 범위와 결과만 제공하는 역할은 그대로입니다. 결과를 Writing Quality Editor나
release assessment에 활용할 수 있지만 결과 자체가 문장 수정·발행을 승인하지는 않습니다. 연관 스킬 계약과
자동 출력 parser는 변경하지 않았습니다. Codex 확장·Windows 검증·선택적 출력 validator는 별도 작업입니다.
이번 기록은 근거와 한계를 갱신하며 릴리스를 공지하지 않습니다.
